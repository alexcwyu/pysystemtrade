Design decisions

Decision Rationale Tradeoff Evidence
Initialize stages once and calculate stage outputs lazily. Shared System context and cache connect forecasting and portfolio computations. The backtest stage flow and production broker stack are separate entry points. System.init (L42) / System._setup_stages (L85)
Resolve storage classes through dataBlob naming and shared handles. Production adapters receive consistent database/access/log objects. Adapter constructors must follow expected naming and argument conventions. dataBlob._add_mongo_class (L139) / dataBlob._add_parquet_class (L171)

Strengths and limits

Strengths

  • Simulation stages and production futures order objects have explicit boundaries. System.init (L42) / System._setup_stages (L85) / ibExecutionStackData._send_broker_order_to_IB (L334)

Limitations

  • IB integration requires a configured broker connection and correctly resolved contract data. ibExecutionStackData._send_broker_order_to_IB (L334)
  • Static inspection of dataBlob is not validation of MongoDB/Parquet installations or persistent data correctness. dataBlob._add_mongo_class (L139) / dataBlob._add_parquet_class (L171)

The linked validation and command records preserve actual historical runs and user-authorized exclusions.
